JAVA BASED CONFIG:-
This is the same idea as XML configuration, but instead of writing bean definitions in spring.xml, we write them in a Java class.
    @Configuration Tells Spring: "This class contains bean definitions."

    @Configuration
    public class AppConfig {
    }

    @Bean is Used to tell Spring which object it should manage its similar to using bean tag in the Spring.xml
    @Configuration
    public class AppConfig {
        @Bean
        public Desktop desktop() {
            return new Desktop();
        }
    }
    Here:
    return new Desktop();  This creates the object, and @Bean tells Spring to manage that object as a Bean. The method name desktop becomes the bean name by default.

    With Java configuration we use:
    ApplicationContext context =
        new AnnotationConfigApplicationContext(AppConfig.class);

BEAN NAME:-
 The default name of bean is the desktop itself so in the AppConfig file if the method name is desktop then the dafault name of the bean will be desktop
 Desktop dt = context.getBean("desktop",Desktop.class);  here the first parameter is the bean name

 for changing the bean name we can specify the name in the @bean annotation like @Bean(name ="bean_name") example :- @Bean(name="com2")
 so in the App.java file we can pass this name Desktop dt = context.getBean("com2",Desktop.class);

 also we can pass multiple names to the name @Bean annotation i.e  @Bean(name= {"com2","desktop1","beast"})
 and among all these names we can use any one name and pass it as a parameter in the App.java i.e  so in the App.java file we can pass this name Desktop dt = context.getBean("beast",Desktop.class);
