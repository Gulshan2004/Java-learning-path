ApplicationContext is an advanced IoC container that manages Spring beans and their lifecycle.

the more the no. of bean created in the Spring.xml for the same class the more object will be crated for that class

getBean() is used to fecth an object from the container it returns of type object

ApplicationContext context = new ClassPathXmlApplicationContext("spring.xml");
here Spring creates bean objects when the container is initialized.

BEAN SCOPE:-
Singeleton (Default):- <bean id="alien1" class = "com.gulshan.Alien" scope="singleton" > </bean>
Only ONE object is created. All references point to the same object.

Prototype Scope :- <bean id="alien1" class = "com.gulshan.Alien" scope="prototype" > </bean>
Every getBean() call creates a new object. also if the scope is set to prototype them the object wil be only created when ypu call getBean() else it wont work

SETTER INJECTION :-
Spring injects values using setter methods.

Class Alien.java:-
public class Alien {
    private int age;
    public void setAge(int age){
        this.age = age;
    }
}

spring.xml:-
<bean id="alien1" class="com.telusko.Alien">
    <property name="age" value="21"/>
</bean>

Spring internally does:
Alien a = new Alien();
a.setAge(21);

REF ATTRIBUTE:-
In the spring.xml in the <property> tag if we want to assign to a primitive type we use value.
but If we want to assign a reference or an object we use "ref"  here  ref ="lap1"  in which we assign the id of that particular object we want to connect the bean with  this avoids creating objects manually
also the bean must be created or should exist  before passing its id to " ref "of another bean.
This is a part of setter injection.

 <bean id="alien1" class = "com.gulshan.Alien" >
    <property name ="age" value ="21"> </property>
    <property name ="lap"  ref ="lap1"> </property>
    </bean>

    <bean id="lap1" class = "com.gulshan.Laptop"> </bean>

CONSTRUCTOR INJECTION:-
instead of using setter injection we can use constructor injection as well which can be done as soon as we have the object created
<constructor-arg value="21"> </constructor-arg>
 we can assign the value using the constructor-arg as well this is difine s inside the spring.xml file itself

    NOTE:-
             <property name ="lap"  ref ="lap1"> </property>
             <constructor-arg value="21"> </constructor-arg>

       this was working when it was single parameterized constructor in alien but wo double parametrized constructor we need to use something else i.e instead of using setter injection here using property
       we can use   <constructor-arg ref="lap1"> </constructor-arg>

    NOTE:-
       In Constructor injection the values are passed based on the order of parameters in the constructor means if
       alien(int age , Laptop lap){
       this.age = age;
       this.lap = lap;
       }
       then  in the spring.xml we can't inject values in the order
               <constructor-arg name="lap" ref="lap1"> </constructor-arg>
               <constructor-arg name="age" value="21"> </constructor-arg>
            here lap is injected first and then age so there are several ways to avoid it which are by using the type and index (Preferred) attribute this avoids the order based error

 AUTOWIRING:-
   <property name ="com"  ref ="com"> </property>
  here its a wire which connects my alien to the laptop so instead of creating it manually , spring should ne smart enough to handle this thing automatticaly so here comes the concept of Autowiring.

    <bean id="alien1" class = "com.gulshan.Alien"  autowire ="byName">  this will automatically search for the field by name using  the autowire ="byName"  attribunte.

    also auto wire only works when   <property name ="com"  ref ="com1> </property>   is not mentioned if this is mentioned then it won't work .

    autowire= "byType" is used when we want search by type instead of by name so
    <bean id="com1" class = "com.gulshan.Laptop"> </bean> instead of referring to  the id it uses the class = "com.gulshan.Laptop" as laptop is a  Computer only.
     <bean id="com2" class = "com.gulshan.Desktop"> </bean> same goes for this provide only one such bean should be present at a time .

    in case both the beans  exists at the same time we then we can use the primary attribute as true hence the autowire attribute  will select that particular bean first  this will avoid confusion between which one to select

LAZY INITIALIZATION OF THE BEAN:-
    In case I dont want to load the desktop object by default when the container loads i dont want this obect to be created i want this to be created only when i call it for the firat time
    to achive this we use the  attribute with the bean of that particular class  :-
         <bean id="com2" class = "com.gulshan.Desktop" lazy-init="true"> </bean>
    so the object will only be created when we want it and it will be Singelto only.

    also we have a Non lazy bean (  Eager ) which is dependent on a lazy bean still it will create the object of lazy beam in that case

GETBEAN BY TYPE :-
    since the getBean() method returns of type object so we need to typeCast it to the type of class of object we want
    Example:-
     Alien obj1 = (Alien) context.getBean("alien1");

    so we can use another getBean() method which take two parameter i.e the bean id and the class type this avoid explixit typcasting
     Alien obj1 = context.getBean("alien1", Alien.class);

INNER BEAN :-
    This concept is used when we dont want to refer a bean outside a class so that others cant use it so we use the concept of inner bean
    here alien refers to computer and laptop is an implimentation of computer hence this laptop bean is available fot the entire application so any one can use it so  we  limit the usage  of this bean by declaring it inside the property tag

    <bean id="alien1" class = "com.gulshan.Alien"  autowire ="byType">
          <property name ="age" value ="21"> </property>
          <property name ="com" >
                    <bean id="com1" class = "com.gulshan.Laptop" primary="true"> </bean>
                </property>
    </bean>

   hence the laptop becomes an inner bean for alien and can only used by the alien
